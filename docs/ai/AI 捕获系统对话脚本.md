下面给你一套 **完整的 AI 捕获对话脚本（Conversation Design）**。

目标是让 **用户通过 2–5 轮对话就能生成一张卡片**，同时保持 **自然聊天 + 结构化信息收集**。

我会给你：

1. 对话整体结构
2. 标准对话脚本模板
3. 不同捕获场景脚本
4. 中间插入操作组件方式
5. 修改与纠错脚本
6. 发布脚本
7. 异常情况脚本

这基本就是 **可以直接交给产品/设计/Prompt工程师落地的 conversation spec**。

---

# 一、对话整体结构（Conversation Flow）

捕获对话推荐 **5阶段结构**：

```
1 用户触发
2 AI理解
3 生成卡片草稿
4 信息补充
5 发布确认
```

完整流程：

```
User Message
     ↓
AI Understanding
     ↓
Draft Card
     ↓
Conversation Filling
     ↓
Review
     ↓
Publish
```

理想轮次：

```
2 — 5 turns
```

---

# 二、标准对话脚本模板（Universal Script）

这是 **所有捕获流程的基础模板**。

### Step 1 用户输入

用户说任何内容：

```
昨天在上海吃了一兰拉面
```

或

```
记录一下这个想法
```

或

```
收藏这个网站
```

---

### Step 2 AI理解 + 草稿生成

AI回复：

```
我帮你生成了一张卡片 👇
```

卡片预览：

```
标题：一兰拉面
类型：地点
地点：上海
标签：拉面
```

然后 AI 提问：

```
需要补充一些信息吗？
```

操作选项：

```
[添加图片]
[添加标签]
[写点备注]
[直接发布]
```

---

# 三、对话组件设计

在对话中插入 **Action UI**。

每个 AI message 可以包含：

```
AI Message
+ Quick Actions
+ Card Preview
```

例如：

```
AI：
要不要加一张照片？

[上传图片]
[跳过]
```

组件类型：

| 组件           | 用途   |
|--------------|------|
| Quick Reply  | 快速选择 |
| Input        | 输入文本 |
| Upload       | 上传   |
| Selector     | 选择标签 |
| Card Preview | 实时卡片 |

# 十二、对话脚本设计原则

### 1 一次只问一个问题

不要：

```
标题是什么？要不要加图片？要不要加标签？
```

---

### 2 尽量用选项

而不是用户输入。

---

### 3 AI先做80%

用户只确认。

---

### 4 对话不超过5轮

否则体验会变差。
