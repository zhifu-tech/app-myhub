# MyHub README.md 生成规则

**本规则定义了 MyHub 基础设施模块（Infra）README.md 文档的结构、内容标准与格式要求**。其核心目的是确保所有基础设施模块的 README 文档具备**清晰的结构**、**一致的表达**和**快速上手的能力**，从而提升开发人员的使用体验和开发效率。

- **版本编号**：v1.0
- **面向的使用者**：`AI Copilot`、开发人员

## 📋 适用范围

本规则适用于所有 MyHub 基础设施模块（Infra）的 README.md 文档，包括但不限于：

- `core:logger` - 日志模块
- `core:navigation` - 导航模块
- `datastore` - 数据存储模块
- 其他基础设施模块

## 1. 文档结构要求

每个基础设施模块的 README.md 必须包含以下核心章节：

### 1.1 文档标题（必需）

**格式**：`# Core [Module Name] Module`

**要求**：

- 使用一级标题（`#`）
- 格式：`Core` + `模块名称` + `Module`
- 模块名称使用首字母大写的驼峰命名（如：`Logger`、`Navigation`）

**示例**：

```markdown
# Core Logger Module

# Core Navigation Module
```

### 1.2 模块概述（必需）

**格式**：一段式描述，使用加粗强调关键信息

**结构模板**：

```text
本模块用于**规范**和**实现** MyHub 应用的[模块类型]基础设施（[Module Name] Infra），为各功能模块**[提供的能力]**。它基于 **[技术选型]**，实现了**[特性1]**、**[特性2]**、**[特性3]**等特性，并提供了面向 KMP 场景的**[架构特点]**，方便在 **[目标平台/场景]**中集成和使用。
```

**要求**：

- 使用加粗（`**`）强调关键信息
- 必须包含：模块作用、技术选型、核心特性、架构特点、目标场景
- 保持简洁，控制在 1-2 句话

**示例**：

```markdown
本模块用于**规范**和**实现** MyHub 应用的日志基础设施（Logger Infra），为各功能模块**提供统一、跨平台的日志记录能力**。它基于 [kotlin-logging](https://github.com/oshai/kotlin-logging) 库，实现了**延迟求值**、**多级别日志**、**标记支持**等特性，并提供了面向 KMP 场景的**统一日志接口**，方便在 **Android、iOS、JVM、Web** 等多端项目中集成和使用。
```

### 1.3 核心组件（必需）

**格式**：`## 核心组件`

**要求**：

- 列出 3-5 个核心组件
- 每个组件使用三级标题（`###`）和编号（`1.`、`2.`、`3.`）
- 组件名称使用代码格式（如：`` `Logger` ``、`` `AppNavigator` ``）
- 每个组件包含：
  - 组件名称（三级标题）
  - 简要描述（一句话）
  - 关键特性或方法（使用列表）

**结构模板**：

```markdown
## 核心组件

### 1. [Component Name]

[组件简要描述]：

- **[特性 1]**：[说明]
- **[特性 2]**：[说明]
- `method()`：[方法说明]
```

**示例**：

```markdown
## 核心组件

### 1. Logger 接口

统一的日志接口，定义所有日志级别的方法：

- **TRACE**：最详细的日志信息，用于深度调试
- **DEBUG**：调试信息，开发阶段的主要工具
- **INFO**：信息性消息，记录重要事件和状态变化
```

### 1.4 使用示例（必需）

**格式**：`## 使用示例`

**要求**：

- 提供完整的、可运行的代码示例
- 使用 Kotlin 代码块（` ```kotlin `）
- 代码示例应包含：
  - 初始化/配置步骤
  - 基本使用场景
  - 常见用法
- 使用注释（`//`）标注步骤编号和说明
- 示例应覆盖主要使用场景，但保持简洁

**结构模板**：

````markdown
## 使用示例

```kotlin
// 1. [初始化/配置步骤]
[代码]

// 2. [创建实例/基本使用]
[代码]

// 3. [常见用法1]
[代码]

// 4. [常见用法2]
[代码]
```

**示例**：
```markdown
## 使用示例

```kotlin
// 1. 配置 Koin
startKoin {
    modules(
        loggerModule {
            LoggerConfig(
                appName = "MyHub",
                useAndroidLogger = true
            )
        }
    )
}

// 2. 创建 Logger 实例
val logger = logger("MyModule")

// 3. 记录日志
logger.info { "Application started" }
```

````

### 1.5 文档链接（必需）

**格式**：`## 文档`

**要求**：

- 链接到架构设计文档
- 使用相对路径（`./docs/[文档名称]`）
- 链接文本应清晰描述文档内容

**结构模板**：

```markdown
## 文档

- [MyHub [模块名称]方案设计](./docs/myhub-[模块名称]-infra-v[版本号].md)
````

**示例**：

```markdown

```

### 1.6 可选章节

以下章节可根据模块实际情况选择添加：

#### 1.6.1 功能特性（可选）

**格式**：`## 📋 功能特性`

**要求**：

- 使用列表列出模块的主要功能特性
- 每个特性使用 ✅ 标记
- 保持简洁，3-8 个特性为宜

**示例**：

```markdown
## 📋 功能特性

- ✅ **Mock HttpClient**: 提供创建 Mock HttpClient 的工具函数
- ✅ **测试支持**: 用于单元测试中模拟 HTTP 请求和响应

```

**格式**：`## 📁 模块结构`

**要求**：

- 使用代码块展示模块的目录结构
- 包含主要源文件和目录
- 使用注释说明关键文件的作用

**示例**：

```markdown
## 📁 模块结构

```

- 说明模块包含的测试

## 2. 内容要求

### 2.1 内容精简原则

README.md 应遵循以下原则：

- ✅ **快速上手**：专注于让开发人员快速了解和使用模块
- ✅ **核心信息**：只包含最核心的组件和使用方法
- ✅ **简洁明了**：避免冗长的说明和过多的细节
- ✅ **可选章节**：可根据模块特点添加可选章节（功能特性、模块结构、依赖关系、测试、注意事项、相关模块、更多示例）
- ❌ **不包含**：
  - 详细的使用指南（应在架构设计文档中）
  - 平台特定配置细节（应在架构设计文档中）
  - 依赖版本信息（应在架构设计文档中）
  - 过于详细的测试说明（简要说明即可）
  - 最佳实践（应在架构设计文档中）

### 2.2 代码示例要求

- ✅ **完整性**：代码示例应该可以直接使用或稍作修改即可运行
- ✅ **注释清晰**：使用注释标注步骤和关键点
- ✅ **覆盖主要场景**：包含初始化、基本使用、常见用法
- ✅ **格式规范**：遵循 Kotlin 编码规范

### 2.3 链接要求

- ✅ **相对路径**：使用相对路径链接到文档
- ✅ **路径正确**：确保链接路径正确，指向实际存在的文档
- ✅ **描述清晰**：链接文本应清晰描述文档内容
