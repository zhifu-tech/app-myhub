# 工程落地建议（Client-first + KMP 架构）

---

## 1. 总体工程策略

系统采用：

```text id="bq3y8u"
Client-first + Local-first + BYO AI Model
```

### 核心原则

1. **客户端为核心执行环境**

    * 对话、状态机、卡片生成全部在客户端完成
    * 服务端不参与核心业务逻辑

2. **服务端仅作为 AI 能力代理（可选）**

    * 提供统一模型接口（Proxy）
    * 不存储用户核心数据

3. **支持用户自定义 AI 模型（BYO Model）**

    * 用户可接入自己的模型 API（如 OpenAI / 本地模型）
    * 系统不依赖中心化 AI 服务

4. **数据主权在本地（Local-first）**

    * 默认不上传卡片正文内容
    * 本地存储为主
    * 云同步为可选能力

---

## 2 客户端架构（KMP 核心）

采用 **Kotlin Multiplatform（KMP）** 构建跨平台统一逻辑层。

### 架构分层

```text id="qf8b9g"
Presentation Layer（UI层）
↓
Domain Layer（业务层）
↓
Data Layer（数据层）
↓
Local Storage（本地存储）
```

---

### 1️⃣ Presentation Layer（UI层）

技术建议：

```
Compose Multiplatform（Android / iOS / Desktop）
```

职责：

* Chat UI（对话界面）
* Live Card Preview（实时卡片）
* Action Components（动态组件）
* 用户输入处理

---

### 2️⃣ Domain Layer（核心逻辑层）

KMP 共享模块（重点）

包含：

```
Conversation Engine
State Machine
Slot Manager
Action Planner
Card Engine
Tool Dispatcher
```

说明：

* 所有核心逻辑在此层实现（跨端复用）
* 不依赖平台能力

---

### 3️⃣ Data Layer（数据抽象层）

职责：

* Repository 模式封装数据访问
* 屏蔽本地 / 远程差异

结构：

```text id="6n9y7k"
CardRepository
ConversationRepository
EmbeddingRepository
ModelConfigRepository
```

---

### 4️⃣ Local Storage（本地存储）

技术建议：

```text id="3m0v9x"
SQLDelight（结构化数据）
+ 文件系统（图片/附件）
+ 本地向量索引（可选）
```

说明：

* 所有卡片数据默认本地存储
* 支持离线使用

---

## 3 AI 能力架构（去中心化）

## 3.1 AI 调用模式

```text id="y6zpjk"
Client
 ↓
Model Adapter（统一接口）
 ↓
[选项A] 用户自定义 API（BYO）
[选项B] 服务端 Proxy（可选）
[选项C] 本地模型（未来扩展）
```

---

## 3.2 Model Adapter（模型适配层）

统一接口设计：

```text id="2q5z6r"
generate(text)
extract(json_schema)
tool_calling(tools)
embedding(text)
```

作用：

* 屏蔽不同模型 API 差异
* 支持多模型切换

---

## 3.3 BYO Model（用户自定义模型）

支持：

* OpenAI API
* OpenRouter
* 本地 LLM（如 Ollama）

用户配置项：

```text id="6b6x1p"
API Key
Base URL
Model Name
```

---

## 3.4 服务端 Proxy（可选）

服务端仅提供：

```text id="9nl0e4"
统一模型调用接口
请求转发
限流 & 监控
```

约束：

* 不存储用户卡片正文
* 不参与业务逻辑

---

## 4 Tool 执行架构（客户端内执行）

所有 Tool 在客户端实现：

```text id="vtd9qv"
create_card
update_card
suggest_tags
extract_entities
summarize_content
publish_card
search_cards
```

---

### Tool Dispatcher

职责：

* 接收 LLM 输出
* 路由到具体 Tool
* 返回执行结果

---

### 优势（补充）

* 无服务端依赖
* 响应速度快
* 数据安全性高

# 总结（工程落地核心）

## 架构转变

从：

```text id="7u8lqe"
Server-first AI System
```

升级为：

```text id="n2b9fw"
Client-first AI Agent System
```

---

## 核心优势

* 数据完全可控（本地优先）
* 支持去中心化 AI（BYO Model）
* 更低延迟（本地执行）
* 更强隐私保护

---

# 📌 备注（工程合理性）

* 该架构符合当前 AI Native App 发展趋势（Local-first / Edge AI）
* KMP 适合统一复杂业务逻辑（尤其是状态机 + Agent）
* 服务端弱化后，对客户端工程质量要求显著提高（需重点投入）
