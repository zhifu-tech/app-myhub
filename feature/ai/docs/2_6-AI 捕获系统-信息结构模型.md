# AI 捕获系统的信息结构模型（Universal Card Schema

---

## 1. 文档定位

* 版本：V1.1
* 类型：AI 捕获系统核心数据结构设计（PRD）
* 作用：定义 AI 捕获系统中 **唯一标准信息结构（Universal Card Schema）**
* 适用对象：

    * 后端工程（Card Engine / Storage）
    * AI工程（LLM Agent / Extraction / Generation）
    * 前端工程（Card UI / Preview）
    * 数据工程（搜索 / 推荐 / 知识图谱）

---

## 2. 术语注释

| 术语                  | 定义            |
|---------------------|---------------|
| Capture             | 将用户输入转化为结构化信息 |
| Card                | 系统中的最小信息单元    |
| Draft               | 未发布的可编辑卡片     |
| Tool                | LLM调用的系统能力接口  |
| Schema              | 数据结构约束规则      |
| Entity              | 从内容中抽取的结构化对象  |
| Relation            | 卡片之间的关系       |
| Block-based Content | 以内容块组织的数据结构   |

---

# 一、设计目标

## 1.1 核心目标

建立一个：

```
统一 / 可扩展 / 可搜索 / 可被 AI 理解
```

的信息结构模型。

---

## 1.2 问题背景

如果没有统一结构：

```
文本 / 图片 / 链接 / 想法
→ 无法结构化
→ 无法搜索
→ 无法推荐
→ 无法形成知识网络
```

---

## 1.3 核心原则

### 原则1：所有信息都是 Card

```
Note / Idea / Link / Image / Task
= Card
```

---

### 原则2：AI 可读 + 系统可控

* AI 可以生成
* Tool 可以修改
* Schema 强制约束

---

### 原则3：结构优先于内容

```
结构稳定
内容可变
```

---

# 二、Universal Card Schema（标准定义）

```json
{
  "id": "string",
  "type": "string",
  "title": "string",
  "summary": "string",
  "content": [
    {
      "type": "text|quote|link|code|list|image",
      "value": "any"
    }
  ],
  "ui": {
    "cover": {
      "icon_key": "string|null",
      "bg_color": "string|null",
      "tint_color": "string|null",
      "image_ref": "string|null"
    }
  },
  "media": [
    {
      "type": "image|video|file|audio",
      "url": "string",
      "caption": "string|null"
    }
  ],
  "tags": [
    "string"
  ],
  "location": {
    "name": "string|null",
    "latitude": "number|null",
    "longitude": "number|null"
  },
  "entities": [
    {
      "type": "string",
      "name": "string"
    }
  ],
  "source": {
    "kind": "manual|link|share|import|extract",
    "ref": "string|null"
  },
  "relations": [
    {
      "type": "related|reference|mention|parent",
      "card_id": "string"
    }
  ],
  "status": "draft|published|archived",
  "created_at": "ISO-8601",
  "updated_at": "ISO-8601"
}
```

---

# 三、字段分层模型（关键设计）

为了对齐系统架构，将字段分为 **5层语义层级**：

```
Core Layer（核心字段）
Content Layer（内容层）
Metadata Layer（元数据）
AI Layer（AI增强字段）
System Layer（系统字段）
```

---

## 3.1 Core Layer（核心字段）

| 字段      | 说明   |
|---------|------|
| id      | 唯一标识 |
| type    | 卡片类型 |
| title   | 标题   |
| summary | 摘要   |

👉 用于：

* 列表展示
* 快速理解
* 搜索入口

---

## 3.2 Content Layer（内容层）

| 字段      | 说明             |
|---------|----------------|
| content | Block-based 内容 |
| media   | 多媒体            |

👉 对齐：

* AI Pipeline（生成 / 摘要）
* UI 渲染系统

---

## 3.3 Metadata Layer（元数据）

| 字段       | 说明 |
|----------|----|
| tags     | 标签 |
| location | 地点 |
| source   | 来源 |

👉 用于：

* 筛选
* 分类
* 推荐

---

## 3.4 AI Layer（语义增强层）

| 字段        | 说明 |
|-----------|----|
| entities  | 实体 |
| relations | 关系 |

👉 对齐：

* Vector DB
* Knowledge Graph
* 语义搜索

---

## 3.5 System Layer（系统字段）

| 字段         | 说明   |
|------------|------|
| status     | 生命周期 |
| created_at | 创建时间 |
| updated_at | 更新时间 |
| ui         | UI配置 |

👉 用于：

* 状态机控制
* 前端展示
* 数据管理

---

# 四、字段详解（工程级定义）

---

## 4.1 type（卡片类型）

### 作用

* 决定：

    * Slot Filling 策略
    * UI 模板
    * AI Prompt 分支

### 标准类型

```
note
idea
article
place
person
event
task
bookmark
quote
```

---

## 4.2 content（内容结构）

### 设计原则

采用：

```
Block-based Content
```

### 优势

* AI 易解析
* UI 易渲染
* 支持多模态扩展

---

## 4.3 media（媒体）

### 与 content 区别

| 字段            | 用途     |
|---------------|--------|
| content.image | 内容中的图片 |
| media         | 独立媒体资源 |

---

## 4.4 tags（标签）

### 来源

```
用户输入
+
AI推荐（suggest_tags Tool）
```

---

## 4.5 entities（实体）

### 来源

```
extract_entities Tool
```

### 用途

* 语义搜索
* 知识图谱
* 推荐系统

---

## 4.6 relations（关系）

### 来源

```
AI 推断 + 用户操作
```

### 示例

```
A → reference → B
```

---

## 4.7 source（来源）

### 类型

```
manual（用户输入）
link（网页）
share（分享）
import（导入）
extract（AI生成）
```

---

## 4.8 status（状态）

### 对齐 State Machine

```
draft → INFO_COLLECT
published → COMPLETE
archived → 历史归档
```

---

# 五、与系统架构的映射关系（核心）

---

## 5.1 与 Conversation Engine

| 模块              | 使用字段                            |
|-----------------|---------------------------------|
| Slot Manager    | title / tags / image / location |
| State Machine   | status                          |
| Context Manager | current_card                    |

---

## 5.2 与 AI Pipeline

| 模块               | 使用字段            |
|------------------|-----------------|
| Entity Extractor | entities        |
| Summarizer       | summary         |
| Tag Recommender  | tags            |
| Generator        | content / title |

---

## 5.3 与 Tool Layer

| Tool             | 操作字段        |
|------------------|-------------|
| create_card      | core fields |
| update_card      | 任意字段        |
| suggest_tags     | tags        |
| extract_entities | entities    |
| publish_card     | status      |

---

## 5.4 与 Card Engine

| 功能        | 作用        |
|-----------|-----------|
| Validator | 校验 schema |
| Formatter | 标准化字段     |
| CRUD      | 数据操作      |

---

## 5.5 与 Storage Layer

| 存储            | 内容                           |
|---------------|------------------------------|
| Relational DB | 全量字段                         |
| Vector DB     | embedding（content + summary） |
| File Storage  | media                        |

# 六、Schema 校验规则（必须）

Card Engine 必须实现：

---

## 6.1 必填字段

```
id
type
title
status
created_at
```

---

## 6.2 类型校验

例如：

```
tags → array<string>
location.latitude → number|null
```

---

## 6.3 状态约束

```
draft → 可编辑
published → 不允许结构缺失
```

# 十一、最佳实践总结

---

## 核心设计原则

```
统一结构 > 灵活内容
AI生成 > 用户填写
结构化 > 自由文本
```

---

## 系统原则

```
Schema = 数据基础
State Machine = 流程控制
Tool = 唯一修改入口
AI = 决策层
```

Universal Card Schema 是整个系统的：

```
数据核心 + AI接口 + UI协议 + 存储标准
```

它决定：

* AI 能否理解信息
* 系统能否扩展
* 数据能否形成知识网络
