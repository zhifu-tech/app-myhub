# 📄 PRD：AI 捕获系统对话脚本（Conversation Spec）V1.0（生产级）

---

# 一、文档信息

## 1.1 基本信息

* 版本：V1.0
* 类型：对话脚本规范（Conversation Spec）
* 适用对象：产品 / 设计 / 前端 / AI工程

---

## 1.2 文档目标

定义一套：

```text
可控（State驱动）+ 可渲染（UI结构化）+ 可执行（Tool联动）
```

的对话脚本系统，使 AI 捕获从：

```text
聊天 → 可执行流程
```

---

# 二、核心设计原则（架构对齐）

## 2.1 三层驱动

```text
State Machine → 控制流程
LLM Agent → 生成话术 & 决策
Response Builder → 生成 UI
```

---

## 2.2 对话本质升级

```text
传统：AI自由回复
现在：AI = 状态驱动 UI 生成器
```

---

## 2.3 强约束规则

```text
1. 对话必须绑定 State
2. 每条 AI 消息必须可结构化
3. UI 组件必须可渲染
4. 所有数据变更必须通过 Tool
```

---

# 三、对话整体结构（State驱动）

## 3.1 五阶段结构（与状态机对齐）

```text
1. USER_INPUT（IDLE）
2. INTENT（INTENT_DETECT）
3. DRAFT（DRAFT_CREATE）
4. FILLING（INFO_COLLECT）
5. REVIEW（CARD_REVIEW）
6. PUBLISH（PUBLISH_CONFIRM）
```

---

## 3.2 标准流程

```text
User Input
↓
Intent Detect
↓
Draft Card
↓
Slot Filling（最多3轮）
↓
Review
↓
Publish
```

---

## 3.3 轮次控制

```text
2–5轮（强约束）
```

---

# 四、对话输出协议（关键升级）

## 4.1 标准 Response 结构

```json
{
  "message": "需要添加标签吗？",
  "components": [
    {
      "type": "selector",
      "field": "tag",
      "options": [
        "美食",
        "餐厅",
        "日本料理"
      ]
    }
  ],
  "card_preview": {},
  "actions": []
}
```

---

## 4.2 组件类型定义

| 类型           | 说明    |
|--------------|-------|
| quick_reply  | 快速选择  |
| selector     | 标签/选项 |
| input        | 文本输入  |
| upload       | 图片上传  |
| card_preview | 卡片预览  |

---

## 4.3 关键变化

👉 不再是：

```text
纯文本对话
```

👉 而是：

```text
结构化 UI 渲染协议
```

# 十四、对话设计原则（强化版）

---

## 14.1 交互原则

```text
1️⃣ 一次只问一个字段
2️⃣ 尽量用选择，不用输入
3️⃣ 支持随时编辑
4️⃣ 支持跳过
```

---

## 14.2 AI行为原则

```text
AI先完成80%
用户只确认
```

---

## 14.3 工程原则（新增）

```text
所有对话必须结构化
所有操作必须可映射 Tool
所有UI必须可渲染
```
