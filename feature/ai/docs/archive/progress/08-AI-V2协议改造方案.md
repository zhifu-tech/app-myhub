# AI V2 协议改造方案（已确认范围）

## 目标

- 将现有 `feature/ai` 从旧输出协议（`intent/title/summary/tags`）升级为 `2_9/2_10/2_11` 定义的 V2 协议。
- 本轮提示词固定中文，不做 i18n 改造。
- 保持“AI 只提议，客户端裁决”的边界：AI 不控制状态机、不直接发布。

## 现状差距（基于代码）

- 当前 Provider 请求 DTO 仍是旧结构：
- `ProviderAnalysisRequest(task,input,context)`（见 `ProviderAnalysis.kt`）。
- 当前 Provider 输出解析仍是旧字段：
- `ProviderAnalysisOutput(intent,title,summary,tags)`（见 `ProviderAnalysis.kt` + `ProviderAnalysisClients.kt`）。
- Direct API prompt 写死中文、写死旧协议字段（见 `DirectApiProviderClient.kt`）。
- `CaptureOrchestrator.handleCaptureAnalysis` 仍按旧字段合并草稿。
- `ConversationEngine.applyCaptureAnalysisResult` 仍消费 `intent`。
- 当前提示词写死中文；本轮维持该策略，i18n 后置。

## 改造范围

### In Scope

- `feature/ai`：请求/响应 DTO、Provider 客户端、解析器、Orchestrator 合并逻辑、Prompt 组装、最小 UI 映射。
- 本轮仅 `direct_api` 路径改造为 V2 闭环。

### Out of Scope（本轮不做）

- 重做整套 ConversationState 状态机。
- 引入复杂 CRDT/OT。
- 大规模重构 Tool 层命令建模。
- `server_gateway` V2 协议改造。
- 提示词 i18n（多语言模板与语言注入）。

## 方案设计

### 1) 协议模型升级（V2 DTO）

新增/替换 DTO（`feature/ai/layer/agent/provider/analysis`）：

- `AiCaptureRequestV2`
- `protocol.version`
- `session(id,turn_id)`
- `draft(version,data)`
- `constraints(required_fields,locked_fields,field_rules,conflict_policy)`
- `input(text,attachments)`
- `context(short_history,active_fields,language,key_facts)`
- `AiCaptureResponseV2`
- `proposals.patches`（JSON Patch）
- `proposals.clarify`
- `signals.publish_ready/needs_clarification`
- `message`

旧 `ProviderAnalysisOutput(intent,title,summary,tags)` 标记废弃，迁移到 V2 解析器后移除。

### 2) Prompt 规范化（本轮固定中文）

新增 `PromptTemplateProvider`（`feature/ai/layer/agent/impl`）：

- 输入：`constraints`，`active_fields`。
- 输出：`systemPrompt + userPromptEnvelope`。

提示词来源：

- 使用 `feature/ai` 资源文件新增 prompt key（仅中文）：
- `feature_ai_prompt_system_v2`
- `feature_ai_prompt_rules_v2`
- `feature_ai_prompt_output_contract_v2`

本轮约束：

1. `context.language` 固定填充 `zh-CN`。
2. `DirectApiProviderClient` 移除硬编码字符串，改为统一 prompt 组装器输出。

### 3) JSON Patch 安全应用层

新增 `PatchApplier`（建议位置：`feature/ai/layer/tool` 或 `orchestrator` 子包）：

- 输入：当前 draft + `proposals.patches` + constraints。
- 规则：
- 仅允许路径：`/title /summary /tags /media /extra/*`
- `locked_fields` 命中则丢弃该 patch
- `add /tags/-` 去重
- `remove` 目标不存在时忽略
- 应用后调用现有 formatter/validator

输出：

- `PatchApplyResult(updatedDraft, droppedOps, conflicts)`

### 4) Orchestrator 流程改造

`CaptureOrchestrator.handleCaptureAnalysis` 改为：

1. 组装 `AiCaptureRequestV2`（含 draft/version/constraints/context.language）。
2. 调用 `providerAnalysisExecutor.analyzeV2(...)`。
3. 对响应执行结构校验与 `PatchApplier`。
4. 将 `message` 追加为 AI 消息；将 `clarify` 映射到 action/提示。
5. `signals.publish_ready` 仅作弱提示，不直接触发 publish。
6. 进入本地 `prePublishCheck` 仍由用户动作触发。

### 5) ConversationEngine 最小改造

- `applyCaptureAnalysisResult(...)` 去 `intent` 依赖，改为：
- 接收 `aiMessage`（response.message）和 `draft`。
- 基于 `slotManager.missingFields(draft)` 决定状态推进。
- 保留现有状态机，不让 AI 驱动状态跳转。

### 6) Server Gateway 路径（后置）

当前 `ServerGatewayProviderClient` 调用 `/api/ai/capture-analysis`，服务端现有路由是 `/api/capture/analysis` 且不是 V2 结构。

本轮不改造 server gateway，仅保留 direct_api V2 闭环。
后续阶段再新增服务端 V2 endpoint 并切换。

## 分阶段执行计划

### Phase 1（协议骨架 + 中文提示词模板）

- 新增 V2 DTO 与 parser。
- 新增 `PromptTemplateProvider` 与中文资源键。
- Direct API 客户端改为 V2 请求+响应。
- 产出：可在 Direct API 模式跑通单轮请求。

### Phase 2（补丁应用 + Orchestrator）

- 落地 `PatchApplier` 与白名单/锁字段规则。
- Orchestrator 改造为 V2 合并链路。
- ConversationEngine 去 `intent` 依赖。
- 产出：从 AI 响应 patch 到 draft 更新闭环。

### Phase 3（稳定性）

- 增加失败降级（invalid JSON / invalid patch 仅丢弃 patch）。
- 增加埋点：`dropped_ops/conflict_count/patch_apply_ms`。

### Phase 4（后置任务）

- server_gateway V2 endpoint 对齐与路由切换。
- prompt i18n（`zh-CN/zh-TW/en`）与语言偏好注入。

## 验收标准

- 协议：
- 请求体结构符合 `2_10`（含 `protocol.version=2.0`）。
- 响应仅消费 `proposals/signals/message`。
- 行为：
- AI 返回不包含 `intent` 也能正常流程。
- patch 非法时不中断会话，只降级为消息提示。
- 提示词：
- 本轮固定中文模板，输出结构稳定且符合 V2。
- 安全：
- `locked_fields` 对应 patch 被拦截。
- 非白名单路径 patch 被丢弃并记录。

## 风险与回滚

- 风险1：模型输出 JSON Patch 不稳定。
- 处理：保留严格 parser + fallback（仅 message，不改 draft）。
- 风险2：旧逻辑仍依赖 `intent`。
- 处理：ConversationEngine 去意图依赖，统一按 draft+missingFields 推进。
- 风险3：server_gateway 与 direct_api 协议不一致。
- 处理：本轮禁用 server_gateway V2 改造，避免混跑。

## 已确认决策

1. 本轮只做 `direct_api` 的 V2 闭环，`server_gateway` 放下一阶段。
2. 本轮不改造提示语言，提示词保持中文，i18n 后置。
3. `conflict_policy` 默认值按文档固定：

- `title=user_wins`
- `tags=merge`
- `summary=append`
