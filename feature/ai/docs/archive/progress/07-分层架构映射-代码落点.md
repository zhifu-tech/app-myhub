# 分层架构映射（按文档约束）

## 目标

- 明确“分层设计”和“各层职责”在代码中的落点，避免职责混杂。

## 代码映射

- `feature/ai/AiScreen.kt`
- `feature/ai/AIViewModel.kt`
- Provider Mode 快速切换入口已在 `AiScreen` 落地，并通过 ViewModel -> Orchestrator 持久化。
- 完整 AI Settings 配置页已在 `feature/settings` 落地并接入 composeApp 导航主链路。

2. Conversation Engine

## 当前约束达成情况

- ViewModel 不再直接执行业务写库，只调用 `CaptureOrchestrator`。
- 发布写入统一经过 `ToolDispatcher -> CardEngine -> StorageGateway`。
- Tool 层已拆分为 `Dispatcher(编排) + Registry(执行)`，职责边界明确。
- Conversation 的状态、槽位、动作规划已独立成层。
- Provider Router 已支持配置化路由与健康检查骨架，并在不可用时降级到 `MANUAL_EDIT`。
- Provider Router 已接入配置持久化、真实探活、重试熔断、真实请求执行路径与轻量观测统计（server gateway + direct api）。
- 已接入后台任务：定时媒体维护 + Provider 指标上报（通过 StartupTask 启动）。

## 下一步

- 完成 Provider Router 真实网络探活与真实请求执行（非骨架模式）。
- 将媒体后处理与垃圾回收从“发布触发”升级为“后台定时调度”。
