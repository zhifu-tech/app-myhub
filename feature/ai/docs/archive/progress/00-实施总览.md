# AI 捕获系统实施总览（Client-first）

## 目标

- 以客户端为主实现捕获系统，默认本地落库与本地发布。
- 严格遵循 docs/ai 架构约束：状态机驱动、Tool 触发写入、Card Engine 统一落库入口。
- 分阶段交付，确保每阶段可运行、可验收、可回滚。

## 架构决议（2026-04-17）

- 采用“会话驱动草稿协同 V2”模式（唯一实现标准）：
- AI 仅提供 proposals（patch/clarify/signals/message），不控制状态机与发布。
- 客户端独占状态机、冲突处理、发布门禁。
- 统一维护单一 `draft` + `draft.version` 作为本地真相源。
- 详细设计见：
- `feature/ai/docs/2_9-AI 捕获系统-会话驱动草稿协同架构V2.0.md`
- `feature/ai/docs/2_10-AI 捕获系统-会话协同协议JSON-SchemaV2.0.md`
- V1 方案废弃，不进入实现。

## 阶段划分

1. Phase 1（已完成）

- 用真实客户端状态机替换 `feature/ai` 的 mock 流程。
- 接入本地 `CardRepository`，实现 `Publish = Local Commit`。
- 完成分层重构：`conversation / agent / tool / cardengine / storage` 五层落地。
- 修复 `deleted -> deleted_at` 的本地数据写入适配。
- 旧 server-first capture 仓库标记为废弃（Deprecated）。

2. Phase 2（已完成）

- 接入 `draft_session` 持久化，支持会话中断恢复。
- 补充 Action Component JSON 协议和渲染注册表。
- 完成更细粒度状态守卫（State Guard）。

3. Phase 3（已完成）

- 已完成：
- `ai_job` 作业记录接入（running/succeeded/failed/queued）。
- Provider Router 配置化与降级骨架（`server_gateway/direct_api/disabled`）。
- Provider 不可用时自动降级到 `MANUAL_EDIT`。
- Provider 真实请求链路接通（server gateway + direct api）。
- `ai_job` 重试/重放基础能力（失败查询、retry、replay）。
- Provider 配置持久化（`ai.mode/endpoint/model/apiKey/timeout/retries`）。
- 健康检查重试与熔断（失败阈值 + 冷却窗口）。
- Provider 错误分类落库（config/auth/timeout/http/parse/unavailable）。
- Provider 观测统计（成功/失败/时延/错误分布）。
- 基础配置入口（AI 页面 Provider Mode 切换并持久化）。
- 后续增强（移入 Phase 4）：
- 完整 Settings 配置页（endpoint/model/apiKey/timeout/retry）与高级校验提示。
- 观测指标上报到统一监控通道。

4. Phase 4（进行中，45%）

- 媒体导入、缩略图、垃圾回收与本地文件一致性事务。
- 检索索引（FTS）与性能优化。
- 备份恢复与安全加固。
- 已完成：
- 媒体后台定时调度（post-process + GC）。
- AI Provider 指标后台上报（analytics）。
- AI 配置页实现并接入主工程（mode/endpoint/model/apiKey/timeout/retries）。
- 待完成：
