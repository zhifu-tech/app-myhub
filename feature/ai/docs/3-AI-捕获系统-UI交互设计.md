# AI捕获系统的UI交互设计V1.0

## 1. 文档定位
- 版本：V1.0
- 类型：AI 捕获系统设计文档
- 阅读方式：先看术语注释，再阅读方案正文。

## 2. 术语注释
- Capture：将输入内容转化为结构化信息。
- Card：系统中的标准信息单元。
- Draft：发布前可编辑的草稿状态。
- Tool：由模型触发、用于执行真实系统动作的能力接口。
- State Machine：用于约束对话流程的状态控制机制。

## 3. 方案正文

这是目前很多 **AI Knowledge / Capture 产品**采用的 UI 模式：**对话驱动 + 实时结构化结果**。

目标体验：

* 用户像聊天一样输入
* AI 自动生成卡片
* 用户通过轻量操作补充信息
* 卡片实时更新

核心原则：

**Chat 用来输入，Card 用来展示结构。**

---

# 一、整体 UI 布局（核心设计）

推荐 **双区域布局**：

```text
+--------------------------------------------------+
|                 Capture Workspace                |
+---------------------------+----------------------+
|                           |                      |
|  Chat Conversation        |   Live Card Preview  |
|                           |                      |
|  AI message               |   Title              |
|  User message             |   Image              |
|  Quick actions            |   Tags               |
|                           |   Summary            |
|                           |                      |
+---------------------------+----------------------+
|             Input Box / Action Bar               |
+--------------------------------------------------+
```

两个核心区域：

**左侧：对话驱动**
**右侧：结构化卡片**

这样用户会感觉：

> “我在聊天生成卡片”。

---

# 二、Chat Conversation 区域

聊天区域包含 3 种消息类型：

```text
AI Message
User Message
Action Message
```

---

## 1 AI Message

AI 给出理解结果或提问。

例：

```text
小志：
我帮你生成了一张卡片 👇
```

下面出现 **卡片摘要 + 操作按钮**。

---

## 2 User Message

用户输入：

```text
昨天在上海吃了一兰拉面
```

或：

```text
加个标签
```

---

## 3 Action Message（关键）

Action Message 是 **对话里的 UI 组件**。

例如：

```text
需要添加图片吗？

[上传图片]
[跳过]
```

这种组件包括：

| 组件           | 作用   |
|--------------|------|
| Quick Reply  | 快速选项 |
| Tag Selector | 标签选择 |
| Upload       | 上传图片 |
| Inline Input | 输入字段 |
| Confirm      | 确认操作 |

---

# 三、Live Card Preview（右侧）

右侧始终显示 **卡片实时预览**。

结构：

```text
┌───────────────────┐
│ Card Preview      │
│                   │
│ Title             │
│ 一兰拉面          │
│                   │
│ Location          │
│ 上海              │
│                   │
│ Tags              │
│ 美食  拉面        │
│                   │
│ Image             │
│ [image preview]   │
│                   │
│ Notes             │
│ 用户备注内容       │
└───────────────────┘
```

特点：

* 实时更新
* 用户可直接编辑

---

# 四、卡片实时更新机制

当用户操作时：

```text
点击标签
上传图片
输入备注
```

系统：

```text
UI → API → Card Engine → DB
```

然后：

```text
Card Preview 自动刷新
```

用户始终看到 **当前卡片状态**。

---

# 五、输入区域设计

底部输入区建议设计成 **AI Assistant 输入栏**。

结构：

```text
+------------------------------------------------+
| 小志，帮我记录…                                |
|                                                |
| [上传] [    输入框    ]          [发送]            |
+------------------------------------------------+
```

按钮：

```text
上传图片
语音输入
添加标签
```

---

# 六、对话中的操作组件设计

## 1 Quick Reply

用于快速回答。

例：

```text
需要添加标签吗？

[美食]
[餐厅]
[日本料理]
[跳过]
```

特点：

* 降低输入成本
* 提高效率

---

## 2 Tag Selector

标签选择组件：

```text
选择标签

[美食]
[旅行]
[产品]
[+新增]
```

---

## 3 Upload Component

图片上传：

```text
要不要添加一张照片？

[上传图片]
[跳过]
```

---

## 4 Inline Input

直接输入字段：

```text
这家店叫什么？

[输入框________]
```

---

# 七、卡片编辑方式

用户可以直接编辑卡片。

两种方式：

### 方法1：对话修改

用户：

```text
标题改成 一兰拉面体验
```

AI更新卡片。

---

### 方法2：直接点击卡片

点击：

```text
Title
```

变成：

```text
[可编辑输入框]
```

---

# 八、卡片操作区

卡片底部建议有：

```text
[发布]
[保存草稿]
[删除]
```

AI也可以触发：

```text
卡片准备好了

[发布]
```

---

# 九、移动端 UI 设计

移动端不能双栏。

推荐 **上下布局**：

```text
+--------------------+
| Chat Conversation  |
|                    |
| AI message         |
| User message       |
| Actions            |
+--------------------+

+--------------------+
| Card Preview       |
|                    |
| Title              |
| Image              |
| Tags               |
+--------------------+

+--------------------+
| Input Box          |
+--------------------+
```

或者：

**卡片浮层模式**

```text
Chat
↓
点击卡片
↓
展开卡片编辑
```

# 十二、UI设计原则

### 1 Chat 是流程

聊天控制流程。

---

### 2 Card 是结果

卡片展示结构。

---

### 3 Action 是操作

操作通过按钮完成。

# 十三、AI捕获 UI 的关键体验

优秀 AI Capture UI 必须做到：

```text
少输入
多选择
实时反馈
结构清晰
```

# 十四、最成熟的设计模式

AI 捕获系统最推荐的 UI 模式：

```text
Chat
+
Live Card
+
Action Buttons
```

```text

```

整个过程 **像聊天一样完成结构化记录**。
