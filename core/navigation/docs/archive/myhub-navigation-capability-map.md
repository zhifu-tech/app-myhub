## 架构定位图

### 按设计理念分类

```text
┌─────────────────────────────────────────────────────────────────┐
│                    设计理念维度                                    │
└─────────────────────────────────────────────────────────────────┘

UI-first / Stack-driven
    │
    ├─ Navigation 3 ⭐⭐⭐
    │   └─ 完全控制返回栈，适合复杂导航
    │
    └─ Voyager ⭐⭐
        └─ 屏幕抽象，简单导航栈管理

Graph-first
    │
    └─ Compose Multiplatform Navigation ⭐⭐⭐⭐
        └─ 基于导航图，自动栈管理

State machine
    │
    └─ Decompose ⭐⭐⭐⭐
        └─ 组件化架构，复杂状态管理
```

### 按复杂度分类

```text
┌─────────────────────────────────────────────────────────────────┐
│                    复杂度维度                                      │
└─────────────────────────────────────────────────────────────────┘

简单场景
    │
    ├─ Compose Multiplatform Navigation ⭐⭐⭐⭐
    │   └─ API 简单，快速上手
    │
    └─ Voyager ⭐⭐⭐⭐
        └─ Tab Navigator 开箱即用

中等复杂度
    │
    └─ Navigation 3 ⭐⭐⭐
        └─ 需要理解 BackStack 和 NavDisplay

高复杂度
    │
    └─ Decompose ⭐⭐
        └─ 需要重构架构，学习曲线陡峭
```

## 推荐方案总结

### MyHub 项目推荐

**首选方案：Navigation 3** ⭐⭐⭐

**理由**：

1. ✅ 完美匹配主导航项独立栈需求
2. ✅ 支持自适应布局，适合未来扩展
3. ✅ 官方 WasmJS 支持，Web 平台有保障
4. ✅ 长期维护，技术债务风险低

**备选方案：Compose Multiplatform Navigation** ⭐⭐

**适用场景**：

- 如果 Navigation 3 实施遇到困难
- 如果项目需要快速上线
- 如果不需要完全控制返回栈
